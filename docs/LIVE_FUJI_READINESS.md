# Live Fuji Readiness

The repo is not live-demo-ready until this command passes against a real deployment config:

```bash
./scripts/check-live-readiness.sh config/fuji.local.json https://YOUR_DEMO_URL --live-verify
```

## Required Inputs

- `config/fuji.local.json` copied from `config/fuji.example.json`.
- A real Fuji C-Chain collateral token address.
- A real ICTT home or lock contract address.
- One or more real remote token contract addresses.
- RPC URLs for every monitored chain.
- A public HTTPS dashboard URL.
- A hosted artifact equivalent to `public/`, generated by `python scripts/package_static_demo.py` or by the live Fuji export path.

## Current Primary References

Avalanche documentation lists these ICM contract addresses:

- `TeleporterMessenger`: `0x253b2784c75e510dD0fF1da844684a1aC0aa5fcf` on all chains/all networks for the current documented major version.
- `TeleporterRegistry`: `0xF86Cb19Ad8405AEFa7d09C778215D2Cb6eBfB228` on Fuji C-Chain.

Those addresses prove the ICM messaging layer reference, not an ICTT bridge deployment. ICTT home/remote contracts are deployment-specific, so this repo must not ship fabricated addresses.

## Live Evidence Rule

Do not present the dashboard as live evidence until:

- readiness output is `ready: true`;
- the dashboard is hosted publicly;
- the public dashboard is backed by live Fuji data;
- the dashboard still includes a visible deliberately induced divergence;
- the evidence bundle for the displayed state is downloadable.

## Static Package

`python scripts/package_static_demo.py` creates `public/` for static hosting. That package is useful for reviewer UX and deployment rehearsals, but `public/deployment-manifest.json` records `ready_for_public_live_demo: false` until the package is generated from live Fuji data and served from a public HTTPS URL.

For a live package, use:

```bash
python scripts/package_static_demo.py --config config/fuji.local.json --public-demo-url https://YOUR_DEMO_URL
```

The manifest embeds the same readiness checks as `check-live-readiness`, so a hosted package can be inspected without trusting a separate report.

## Live Contract Verification

Use `--live-verify` on the readiness command before presenting the dashboard as live evidence. It performs read-only `eth_getCode` calls against every configured collateral, home, and remote token contract address. Empty bytecode or RPC failure fails readiness.
